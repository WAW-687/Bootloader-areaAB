# STM32 OTA 远程固件更新系统（Bootloader-areaAB）

基于 **STM32F103C8T6** 的完整 OTA（Over-The-Air）固件升级方案：双分区 Bootloader + ESP-01S 联网下载固件 + W25Q64 外部存储 + 自建 TCP 服务器，全链路已实测闭环。

## 系统架构

```
                    ┌─────────────────────────────────────────────┐
                    │  OTA服务器（Python，花生壳内网穿透到公网）      │
                    │  version.txt（版本号）+ App.bin（固件）       │
                    └──────────────────┬──────────────────────────┘
                                       │ TCP: GETVER / UPDATE / DATA 分块拉取
                    ┌──────────────────┴─────────────┐
                    │  ESP-01S（AT指令，USART2）       │
                    └──────────────────┬─────────────┘
        ┌──────────────────────────────┴──────────────────────────────┐
        │                 STM32F103C8T6（64KB Flash）                  │
        │  ┌────────────────────┬  ┌─────────────────────────────┐   │
        │  │ Bootloader 20KB    │←─│ App 44KB（温湿度监测系统）    │   │
        │  │ 0x08000000~4FFF    │  │ 0x08005000~FFFF             │   │
        │  │ 命令行/搬运/跳转    │  │ DHT11+OLED+光敏+OTA客户端    │   │
        │  └─────────┬──────────┘  └──────────┬──────────────────┘   │
        └────────────┼────────────────────────┼──────────────────────┘
                     │      SPI1              │
                     ▼                        ▼
              W25Q64（8MB 外部Flash）    固件暂存块0 + 元数据扇区0x7FF000
```

## Flash 分区与存储布局

| 区域 | 范围 | 用途 |
|---|---|---|
| Bootloader（B区） | 内部 Flash `0x08000000~0x08004FFF`（20KB） | 开机分流：2s 命令行窗口 / OTA 搬运 / 跳转 App |
| App（A区） | 内部 Flash `0x08005000~0x0800FFFF`（44KB） | 业务固件（IROM1=0x8005000，VECT_TAB_OFFSET=0x5000） |
| W25Q64 块0 | `0x000000`，64KB | 待升级固件暂存区 |
| W25Q64 块1~9 | `0x10000~`，各64KB | 备用固件槽（命令行 [5] 下载） |
| W25Q64 元数据 | `0x7FF000`，最后4KB | OTA_InfoCB：OTA_flag(0xAABB1122) + Firelen[11] + OTA_ver[32]，共80字节 |

## OTA 全链路流程

1. **A区开机** → 读 W25Q64 元数据本地版本 → 连 WiFi → 连花生壳域名发 `GETVER`
2. **版本比较**：服务器版本 > 本地 → 发 `UPDATE` 拿 `LEN/CRC` 头
3. **分块下载**：按 1KB 发 `DATA <偏移> <长度>` 逐块拉取（块残缺自动重收，天然断点续传），每块写前先擦好块、收齐即写 W25Q64 块0，WEL 确认 + 页级回读重写自愈
4. **整包校验**：回读算 CRC16-XMODEM，与服务器一致才置 `OTA_flag=0xAABB1122` 并复位；**任何失败不置标志，老固件照常跑，永不变砖**
5. **B区搬运**：复位后 Bootloader 检测魔数 → 擦 App 区 44 页 → 从 W25Q64 块0 逐页搬运（三重防护：长度非0/不超44KB/4字节对齐）→ 清标志 → 复位跳转新固件

## 快速上手

**编译**：两个 Keil 工程均为 AC5 + 标准库 V3.5，直接打开各自 `.uvprojx` 编译；生成 bin 需在 User 选项卡 After Build 勾选：
```
C:\Keil_v5\ARM\ARMCC\bin\fromelf.exe --bin -o $L@L.bin #L
```
**注意**：调试 A 区（App）时烧录器选"扇区擦除"并只保留 App 区算法，防止抹掉 Bootloader。

**服务器**：
```bash
python OTA服务器/ota_server.py     # 监听8080，需花生壳映射（TCP → 127.0.0.1:8080）
python OTA服务器/probe_tunnel.py   # 一键探针：VER=全通 / HTTP=隧道未生效 / 拒连=客户端离线
```
发布新版本 = 改 `OTA服务器/version.txt` + 替换 `App.bin`（见 .gitignore 说明），无需重启。

## 硬件连接

| 外设 | 引脚 |
|---|---|
| ESP-01S | USART2：PA2(TX)→RXD，PA3(RX)←TXD |
| W25Q64 | SPI1：PA4(CS) PA5(SCK) PA6(MISO) PA7(MOSI) |
| DHT11 | PB11（10k 上拉） |
| OLED 0.96" | PB8(SCL) PB9(SDA) |
| 调试串口 | USART1：PA9/PA10，115200 |

⚠️ ESP-01S 与其他 3.3V 负载共电源时，其 VCC 需就近并联 ≥100µF+100nF（发射瞬间 300mA 尖峰会拉垮电源轨，曾导致反复复位与 Flash 写入静默失败）。

## 已知经验教训（写在代码里的防御）

- **NOR Flash 先擦后写**：编程是按位与（1→0），不擦直接写=数据叠加损坏
- **WEL 必须回读确认**：W25Q64 在写使能未置位时收到编程命令会**静默忽略**（不报错、回读全FF）
- **UART 流式接收要紧密消费**：115200 下 22ms 不读就溢出 256B 环形缓冲——大文件传输用分块拉取协议
